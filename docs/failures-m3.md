## 第三批新增字段的失败归因

### 身份证 idcard（100.00%，失败 0 行）

五类扰动全对（含 15→18 位展开）。满分来自**强闸门设计**：GB 11643-1999 的校验位可以**独立重算**——任何候选规范化结果都必须通过校验位重算才被接受（15 位展开、形近字母修复、分隔符剥离都先产出候选、再验校验位）。所以 idcard 上「先猜后验」是安全的：猜错必被闸门挡下、回落到原样返回，**不可能把干净值改坏**。

| 扰动 | 结果 | 归因 | 代表案例（脏 → 真） |
|---|---|---|---|
| abbrev | 40/40 对 | 15 位旧号展开为 18 位：补 `19` 世纪 + 重算校验位。 | `110412760513150` → `110412197605131500` |
| typo | 40/40 对 | 数字形近字母（`O→0 l→1 Z→2 …`）修复，修完必过校验闸门。 | `11041219760513150O` → `110412197605131500` |
| sep | 40/40 对 | 去分隔符后过校验闸门。 | `1104121976-05-131500` → `110412197605131500` |
| space | 40/40 对 | 去空白后过校验闸门。 | `11041219760513 1500` → `110412197605131500` |
| noise | 40/40 对 | 去「（本人）」等噪声后缀后过校验闸门。 | `110412197605131500（本人）` → `110412197605131500` |

- **改坏 0 条**：与 phone 同理，闸门保证「猜错 = 原样返回」，不误伤干净值。
- **口径代价**：15→18 展开固定补 `19`，2000 年后出生者的 15 位号无法还原（信息缺失），原样返回。

### 邮箱 email（52.50%，失败 95 行）

五类扰动里 space / noise 全对，失败集中在 **sep（0/40）/ abbrev（0/40）**，以及 **typo（成功 25/40）**。

| 扰动 | 结果 | 归因 | 代表案例（脏 → 真） |
|---|---|---|---|
| space | 40/40 对 | 去空白。 | `sbe1hdy@ hotmail.com` → `sbe1hdy@hotmail.com` |
| noise | 40/40 对 | 去尾随标点等噪声。 | `sbe1hdy@hotmail.com。` → `sbe1hdy@hotmail.com` |
| typo | 25/40 对 | **只修「位置可判定」的字符**：TLD 必是字母（`hotmai1`→`hotmail`）、域名主体黑白分明恰 1 个异类（`h0tmail`→`hotmail`）、user 首字符必是字母。**user 段内部的错字不可判，不猜。** | 成功：`sbe1hdy@hotmai1.com` → `sbe1hdy@hotmail.com`；失败：`i1hgffldzze@163.com`（真值 `i1hgffldz2e@163.com`，错字在 user 段） |
| sep | 0/40 对 | 邮箱没有校验和，`_` 无法判断是分隔符还是合法字符——**盲删会改坏含 `_` 的干净邮箱**，按「不猜」原样返回。 | `sbe1hd_y@hotmail.com` → 真值 `sbe1hdy@hotmail.com`（原样返回） |
| abbrev | 0/40 对 | 缺 TLD（`.com`）是信息缺失，不可恢复。 | `sbe1hdy@hotmail` → 真值 `sbe1hdy@hotmail.com`（原样返回） |

- **52.50% = (40 + 40 + 25) / 200**，其中 sep / abbrev 的 0% 是**「不猜」口径的理论上限，不是缺陷**。
- **改坏 0 条**：95 条失败全是「原样返回」的漏改，没有一条把合法邮箱改错；干净值未被误伤。
- **修复激进程度必须匹配闸门强度**（本项目定式）：idcard / phone 有强闸门（校验和 / 形态正则）⇒ 敢在任意位置盲修；email 只有宽松形态门 ⇒ 只修「位置本身可判定」的字符。这是 email 分数低于 idcard 的根本原因。

## 老六类字段的归因（M2 老账，数字与 M2 定版逐位一致）

person / address / phone / company / amount / date 六个数字**逐位复现 M2 定版**，归因与代表案例见 [failures-m2.md](failures-m2.md)，此处不重复。要点：

- **person 72.00%**：abbrev 缺字不可恢复 40/40；typo 错字不在表里 16/40；改坏 0。
- **company 81.00%**：abbrev 天花板 2/40（只有「股份有限公司 → 股份公司」能无歧义补回）。
- **address 90.50%**：abbrev 缺省段不可恢复 19/40；「市 / 市中区」歧义型改坏 8 条（全量口径，heldout 占 2）——根因是真实区县表缺失。
- **date 84.00%**：abbrev 8/40（只有「缺零」型可无损还原）。
- **amount 100.00% / phone 100.00%**：五类全对。

**新增 idcard / email 对老六类零影响**：八类接入后老六类产物逐位不变，heldout 数字逐位复现 M2 定版。

## 合成数据的局限

评测集是程序化扰动生成的。身份证 / 邮箱的**形态分布由生成器决定**（如 15 位号的生日范围 1970–1999、邮箱缩写只有「缺 TLD」一种形态），所以这里的数字说明的是规则在**这些扰动类型**上的表现，不能代表真实业务数据。区划随机组合、手机号段只保形状等问题见 failures-m1.md。

## 如何复现评测

在仓库根目录执行。同一个 seed 生成的数据逐字节一致；产物写到 `benchmarks/results/`，这个目录不入库。
（加入 idcard / email 后，`--impl rules` 默认即评**八类**，命令本身没变。）

```bash
# 规范化：heldout（定版数字，只跑一次）
uv run --project . python -m benchmarks.evaluate --impl rules

# 规范化：train（调参参照，可反复跑）
uv run --project . python -m benchmarks.evaluate --impl rules --split train

# 去重：train（真实水平基准）
uv run --project . python -m benchmarks.evaluate_dedupe --split train --threshold 0.85 --adaptive

# 去重：heldout
uv run --project . python -m benchmarks.evaluate_dedupe --split heldout --threshold 0.85 --adaptive
```

失败明细在 `benchmarks/results/failures-rules-heldout.jsonl`（规范化）与 `dedupe-errors-{train,heldout}.jsonl`（去重）。
⚠️ 失败案例里带真值，这是「失败案例公开」口径有意为之；脱敏开关留到发布前再定。

> 开发纪律：heldout 只在定版后跑一次报数。调规则只看 train 的失败样本。
> **M3 定版数字已锁定（2026-10-09）**：任何对规则或数据的改动都会使本表作废，须重跑 heldout 重定版。
