## M2 新增字段的失败归因

### 金额 amount（100.00%，失败 0 行）

五类扰动全对（含 abbrev 的万元展开）。

**过程如实说明**——amount 的 100% 不是一次到位，评测**口径**经过两轮修正（规则本身没动过）：

1. **TASK-018 遗留的口径冲突**：最早的干净集把金额同时写成「带千分位」和「纯数字」两种形态（heldout 40 行里 22 行带逗号），而规则侧闸门是 `^\d+(\.\d+)?元$`（不允许逗号）——**单值输出不可能同时命中两种真值**，导致分数被锁在 40.88%。
2. **TASK-020 修正**：干净集统一为**纯数字**口径（千分位只作为 `sep` 扰动出现），并去掉万元记法的 `:.4f` 截断（改 `:.10g`）⇒ 99.00%。
3. **TASK-021 修正**：干净值的小数**末位改取 1–9**，杜绝 `88982.0` 这种冗余尾随零（万元记法经浮点后必然丢失该位、truth 与规范值逐字符不等）⇒ **100.00%**。

结论：amount 的失败**已清零**；这是一次「**评测基准口径修正**」，不是对规则的调参凑分。

### 日期 date（84.00%，失败 32 行）

五类扰动中四类 100%（noise / sep / space / typo），失败**全部在 abbrev**：

| 扰动 | 结果 | 归因 | 代表性案例（脏 → 真） |
|---|---|---|---|
| abbrev | 8/40 对，32 失败 | **缺年 / 年月不可恢复**。评测集的日期缩写有三种形态：① 缺零（`2026-1-5`）——无损，补零即可；② 年月（`2023-11`）——缺「日」；③ 缺年（`3-26`）——缺「年」。②③ 是**真实的信息缺失**，没有依据补回，按「不猜」原样返回。 | `2023-11` → `2023-11-24`、`3-26` → `2010-03-26` |
| typo | 40/40 对 | 数字形近字母（`O→0 l→1 Z→2 …`）修复，修完过校验闸门。 | `1996-11-0T` → `1996-11-07` |
| sep / space / noise | 全对 | `/ . ／ ．` 归一为 `-`；去空白；去「日期：」前缀、「（录入日期）」后缀、尾随标点。 | `2013/03/16` → `2013-03-16` |

- **20.00% = 8/40 正好是「不猜」策略的理论上限**（只有缺零型可无损还原），**不是缺陷**。
- **改坏 0 条**：32 条失败全是「原样返回」的漏改，没有一条把合法日期改错；干净值未被误伤。
- **校验闸门未在评测集上触发**：规则里有范围闸门（年 1970–2026 / 月 01–12 / 日 01–31），但评测集的日期**只生成合法值**，因此 heldout 里没有越界样本——闸门的作用是「防止形近修复或分隔符归一把值改坏」，在这批数据上体现为「零误伤」。（口径代价的另一面：若真实数据里出现 `2019-13-01` 这类越界值，规则同样会选择原样返回而不是硬凑。）

## 老四类字段（M1 老账，数字与 M1 定版逐位一致）

person / address / phone / company 的四个数字**逐位复现 M1 定版**（72.00 / 90.50 / 100.00 / 81.00），归因与代表案例见 [failures-m1.md](failures-m1.md)，此处不重复。要点：

- **person 72.00%**：abbrev 缺字不可恢复（40/40）+ typo 错字不在表里（16/40）；改坏 0。
- **company 81.00%**：abbrev 天花板 2/40（只有「股份有限公司 → 股份公司」能无歧义补回）。
- **address 90.50%**：abbrev 缺省段不可恢复 17/17；另有「市 / 市中区」歧义型改坏 8 条（全量口径，heldout 占 2）——根因是真实区县表缺失。
- **phone 100.00%**：五类全对；⚠️ 题量小（生成器的形近错字只有 6 对），100% 里有题目少的成分。

**新增 amount / date 对老四类零影响**：两轮数据重生成后老四类产物逐字节不变，heldout 数字逐位复现。

## 合成数据的局限

评测集是程序化扰动生成的。金额/日期的**形态分布由生成器决定**（如日期的缩写只有「缺零 / 年月 / 缺年」三种），所以这里的数字说明的是规则在**这些扰动类型**上的表现，不能代表真实业务数据。区划随机组合、手机号段只保形状等问题见 failures-m1.md。

## 如何复现评测

在仓库根目录执行。同一个 seed 生成的数据逐字节一致；产物写到 `benchmarks/results/`，这个目录不入库。
（加入 amount / date 后，`--impl rules` 默认即评**六类**，命令本身没变。）

```bash
# 规范化：heldout（定版数字，只跑一次）
uv run --project . python -m benchmarks.evaluate --impl rules

# 规范化：train（调参参照，可反复跑）
uv run --project . python -m benchmarks.evaluate --impl rules --split train

# 去重：train（真实水平基准）
uv run --project . python -m benchmarks.evaluate_dedupe --split train --threshold 0.85 --adaptive

# 去重：heldout
uv run --project . python -m benchmarks.evaluate_dedupe --split heldout --threshold 0.85 --adaptive
```

失败明细在 `benchmarks/results/failures-rules-heldout.jsonl`（规范化）与 `dedupe-errors-{train,heldout}.jsonl`（去重）。
⚠️ 失败案例里带真值，这是「失败案例公开」口径有意为之；脱敏开关留到发布前再定。

> 开发纪律：heldout 只在定版后跑一次报数。调规则只看 train 的失败样本。
> **M2 定版数字已锁定（2026-10-09）**：任何对规则或数据的改动都会使本表作废，须重跑 heldout 重定版。
